---
title: "Chat sessions and conversation context"
description: "Sessions are persistent conversations with one or more agents, with automatic context summarization so long conversations never hit a hard token limit."
---

A session is a persistent conversation between you and one or more agents. Every message you send and every reply the agent generates is stored, so your conversations survive restarts and remain available for review. When you create a session you give it a title and specify which agent (or agents) will participate. You are automatically recorded as the session owner.

## Session fields

| Field | Type | Description |
|-------|------|-------------|
| `ID` | string | Unique session identifier (UUID) |
| `UserID` | string | ID of the user who owns the session |
| `Title` | string | Human-readable session name |
| `Model` | string | AI model associated with the session |
| `ContextMessages` | array | The agent's compressed working conversation history |
| `ContextSummary` | string | LLM-generated summary of older turns, prepended to each request |
| `CreatedAt` | timestamp | When the session was created |
| `UpdatedAt` | timestamp | When the session was last updated |
| `DeletedAt` | timestamp or null | `null` if active; set when the session is soft-deleted |

## Messages

Each turn in a conversation is a `Message`. Messages have one of the following roles:

| Role | Description |
|---|---|
| `user` | A message you sent |
| `assistant` | A reply generated by the agent |
| `tool` | The result of a tool execution, returned to the agent |

Messages are ordered chronologically within a session and cannot be reordered.

## Context window management

LLMs have a finite context window. As a conversation grows, AstroClaw automatically manages the context budget so you never hit a hard limit mid-conversation.

When the active context exceeds the session's context budget:

1. The agent asks the LLM to summarize the oldest turns into a compact summary.
2. Those turns are dropped from the active working context.
3. The summary is prepended to future requests as "Previous conversation summary: …", so the agent retains awareness of what happened earlier.

If summarization fails or the context is still over budget, AstroClaw falls back to dropping the oldest messages directly.

The full message history is always retained in the database — only the agent's working context window is compressed.

## Session membership

Sessions have an owner — the user who created it. A guest member role is planned as a foundation for future group chat support.

Each session is linked to one or more agents. When you send a message, you specify which agent should reply, so you can direct requests to different agents within the same session.

## Real-time updates via WebSocket

While a reply is being generated, AstroClaw pushes state snapshots to connected WebSocket clients. Each push contains the full current state of the reply — no delta accumulation needed. This means a client that reconnects mid-stream recovers immediately. The possible status values are:

| Status | Meaning |
|---|---|
| `streaming` | The agent is generating text |
| `tool_calling` | The agent is executing a tool |
| `done` | The reply is complete |
| `error` | An error occurred |

## Session lifecycle

<Steps>
  <Step title="Create a session">
    Call `POST /sessions` with a title and one or more agent IDs. You receive a session ID.
  </Step>
  <Step title="Send messages">
    Call `POST /sessions/{id}/reply` with your message text and the target agent ID. The agent's response is returned, and both the user message and agent reply are persisted.
  </Step>
  <Step title="Context is managed automatically">
    As the conversation grows, older turns are summarized and the active context window is kept compact. You do not need to manage this yourself.
  </Step>
  <Step title="Delete when done">
    Call `DELETE /sessions/{id}` to soft-delete the session. The `deleted_at` timestamp is set, but no data is physically removed from the database.
  </Step>
</Steps>
